# Agent Note: 假设驱动的调试工作流

Status: implemented

[English](2026-09-21-hypothesis-driven-debug-workflow.md) | 中文

## Problem

预设中的调试工作流提示词要求模型调查问题、在自认为找到根因时应用临时修复，并围绕该修复添加插桩。因此第一次 `finish_debug` 审查测量的是未经证实的修复已经改变过的世界，捕获的日志条目无法区分「这个改动是原因」还是「这个改动改变了行为」，而错误的修复没有任何「哪些候选原因已被排除」的记录，会重新进入循环。提示词还把循环的终止交给模型自己的判断，而产品的决策点是用户对 `finish_debug` 回答 **Mark as fixed**（标记已修复）。

## Decision

`@deepseek-ai/dsh-debug` 的部署持有 `prompt` —— 由 [standard、ptc 与 cordis 预设](../../../../packages/bundle/web-app/README.zh.md) 以相同方式挂载 —— 现在是一个假设驱动的循环：

1. 检查代码并调查问题，然后定义 5 个假设，解释用户为何遇到该问题。
2. 添加临时的 `[debug-mode]` 插桩，为每个假设提供证明，把证据 POST 到回环 debug-log 端点。
3. 带着复现步骤调用 `finish_debug` 并停止。

当用户回答 **Proceed**（继续）时，模型读取捕获的条目，修复被证实的假设，跳过被否决的假设；当没有任何假设被数据证实时，生成新的假设并在必要时相应地修改插桩，然后再次调用 `finish_debug`。该循环重复，直到用户按下 **Mark as fixed**，此时模型移除所有 `[debug-mode]` 插桩并保留修复。

临时修复步骤已被移除：一个假设只有当捕获的数据证实它之后才会变成修复。机制没有变化 —— 相同的 `debug:policy` 段落、相同的回环端点、相同的 `finish_debug` 契约；改变的只有预设挂载的提示词文本。

## Alternatives considered

**保留临时修复，并在其旁侧添加假设追踪。** 修复与假设会成为两个相互竞争的因果理论，且捕获的条目仍然测量的是未经证实的修复已经改变过的世界；移除修复更廉价，而修复会作为被证实假设的后果重新出现。

**把假设规则放进 `finish_debug` 工具描述。** 该工具在调试模式未激活时保持注册，因此它的描述是一个稳定的、始终存在的 schema；假设工作流只适用于激活的会话内部，而这正是模式范围内的 `debug:policy` 段落存在的理由。

**把假设数量设为配置字段。** `{ prompt }` 配置契约刻意只包含这一个字段；数量是提示词内容，不是随部署变化的可调参数，因此它位于提示词文本中。

## Consequences

上线的提示词更长了，因此激活的调试模式每次请求增加更多 token。第一次审查循环现在返回五个候选原因的证据，而不是一个临时修复的行为；五个假设都没有被证实的会话要多花一轮审查（新假设、重新插桩、再一次 `finish_debug`）。循环的终止条件是对方的 **Mark as fixed** 回答，而不是模型的判断。

[包 README](../../../../packages/debug/debug-mode/README.zh.md) 与[子系统页面](../../../../docs/subsystems/debug.zh.md) 用假设驱动的语言描述该循环；确切的提示词措辞由预设 `agent.cordis.yml` 文件拥有。
